# 배포 가이드

- **호스팅**: GitHub Pages (`main`에 push → GitHub Actions가 빌드·배포)
- **도메인**: `haenarueng.com` (등록기관: Spaceship)
- **레포**: `codeead/haenaru_website`
- 관리자 화면(CMS)은 쓰지 않는다. 콘텐츠는 레포에 직접 커밋한다 → `docs/시공사례-올리는법.md`

# A. 평소 배포 (한 번 설정한 뒤로는 이것만)

```bash
git add .
git commit -m "변경 내용"
git push
```

push하면 끝이다. `.github/workflows/deploy.yml`이 자동으로 `npm ci && npm run build` 후 GitHub Pages에 올린다. **1~2분 소요.**

진행 상황은 GitHub 레포 → **Actions** 탭에서 본다. 초록 체크가 뜨면 반영 완료.

> **push 전에 `npm run build`를 한 번 돌려본다.** 워크플로우도 같은 명령(`astro check` 포함)을 쓰기 때문에, 로컬에서 실패하면 Actions에서도 똑같이 실패한다. 로컬에서 먼저 잡는 게 빠르다.

배포가 실패하면 Actions 탭에서 빨간 X를 눌러 로그를 본다. 가장 흔한 원인은 시공사례 frontmatter의 오타(카테고리 값, 사진 경로)다.

# B. 최초 1회 설정

아래는 처음 한 번만 하면 된다. 코드 쪽은 이미 다 반영되어 있고, GitHub·Spaceship 웹 화면에서 클릭으로 하는 작업이다.

## B-1. 레포 공개 + Pages 활성화

1. 레포가 **Public**인지 확인 (커스텀 도메인 무료 조건).
2. 레포 → **Settings → Pages → Build and deployment → Source**를 **`GitHub Actions`**로 선택.
   - 이걸 안 하면 push해도 배포가 붙지 않는다.

> `명함.jpeg`(계좌번호 포함)는 `.gitignore`에 있어 커밋되지 않는다. 커밋 히스토리에도 없는 것을 확인했다.

## B-2. Spaceship DNS 설정

현재 도메인은 Spaceship 파킹 페이지를 가리키고 있다. 네임서버(`launch1/launch2.spaceship.net`)는 이미 Spaceship 것이므로 **네임서버는 건드리지 않고 레코드만 교체**한다.

spaceship.com 로그인 → **Domains** → `haenarueng.com` → **DNS records** → **Custom records**

1. **기존 파킹 A 레코드(`54.149.79.189`, `34.216.117.25`)를 먼저 삭제한다.**
   - 안 지우면 DNS가 GitHub과 파킹 페이지를 번갈아 응답해서, 새로고침할 때마다 사이트가 보였다 안 보였다 한다. 가장 흔한 실수.

2. A 레코드 4개 추가 (Host는 전부 `@`):

   | Type | Host | Value |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |

3. `www`도 쓰려면 CNAME 1개 추가:

   | Type | Host | Value |
   |---|---|---|
   | CNAME | `www` | `codeead.github.io` |

   등록해두면 GitHub이 `www.haenarueng.com` → `haenarueng.com`으로 자동 리다이렉트한다.

## B-3. GitHub에 도메인 연결

레포 → **Settings → Pages → Custom domain**에 `haenarueng.com` 입력 → Save.

- DNS 검증에 실패하면 아직 전파 전이다. 잠시 후 재시도.
- 검증을 통과하면 인증서가 자동 발급되고, 그 뒤 **Enforce HTTPS** 체크박스가 활성화된다 (보통 몇 분, 최대 24시간).
- `public/CNAME` 파일이 레포에 있어서 빌드 산출물에 도메인이 항상 포함된다. Actions 배포에서 커스텀 도메인이 풀리는 사고를 막아준다.

## B-4. 확인

```bash
dig +short haenarueng.com A      # 185.199.10x.153 4개만 나와야 정상
dig +short www.haenarueng.com    # codeead.github.io. 로 이어지면 정상
curl -sI https://haenarueng.com | head -1
```

전파는 보통 10분~1시간. 브라우저에서 `https://haenarueng.com` 접속해 사이트가 뜨면 완료.

# C. 도메인을 바꾸게 되면

아래 4개 파일을 **반드시 함께** 고친다. 한쪽만 바꾸면 canonical/OG 주소나 sitemap이 옛 도메인을 가리킨다.

- `astro.config.mjs` — `site`
- `public/CNAME`
- `public/robots.txt` — Sitemap 절대 URL
- `src/layouts/BaseLayout.astro` — canonical/OG 폴백
